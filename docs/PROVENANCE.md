## 引用格式修复（2026-10-27）

`fix/source-quote-ellipsis-20261027` 在 REN 的通用 SourceCompiler 中修复模型使用省略号缩写原文引用的问题。原样引用与唯一大小写还原保持既有行为；带 `...` 或 `…` 的引用仅在前后文字按顺序唯一定位到当前观察中的同一行、同一句/分句时，恢复为实际连续原文片段。跨行/句子、省略首尾锚点、多个可能片段或不存在的文字仍拒绝。不是根据动作、任务标签或评分结果猜原文。

规则统一用于所有模型，本次新增逻辑只还原 `source_quote`。既有的显式时钟类型归一化按原规则继续执行，变化仍单独记录；不根据任务语义猜测或补写动作/触发条件。原始模型响应和缓存保持原样，还原前后引用写入 `compilation.jsonl` 的 normalizations。恢复后的提案继续经过原有 action/trigger/scope 语义审核，不自动进入已接受账本。未修改提示词、输出协议、Jev 阈值或查询策略。

这是明确的适配版本变化，历史成绩保留；修复版使用新目录、新缓存独立评测，不能将历史漏报数直接换算成修复收益。

## 4B 继续运行兼容修复（2026-10-27）

在前一版明确省略号还原之外，支持未写省略号的一处中间省词：引用至少四词，至少两词连续字面前缀；枚举一处缺口，前后字面锚点必须在同一观察行/句或分句中唯一指向同一连续原文。没有字词替换、重排、任务标签查询或模型专用分支；无依据和歧义仍拒绝，提案语义审核保留。

无效的条件拆解（同ID冲突记录、缺少/额外ID）接入已有的 malformed-decomposition 回退：使用已接受意图的完整原始 trigger 与既有路由，不选择或合并某条冲突拆解，不重抽模型答案，也不直接断言条件为真。冲突仅影响该ID；缺失/额外ID使整批拆解被拒绝。原始响应保留，处理原因与原记录写入 contract_normalizations.jsonl。正常与完全相同重复记录沿用原结果。

这是新的统一兼容版本；旧批次、旧失败及其缓存保留。续跑使用固定代码和新结果目录，只复用通过相同请求/响应来源校验的缓存，不把不同版本轨迹拼成一个周成绩。


## 编译截断的统一保守失败处理（2026-10-27）

用户明确选择：意图编译回答因输出长度截断时，整批记为失败，不解析或采用半截提案，保留此前账本继续。规则用于当前 verified REN 的三类结构化编译：意图提案 `compile`、条件拆解和公共观察事实。意图提案整批拒绝并保留原账本；条件拆解整批拒绝并使用既有完整 trigger 回退；公共事实整批拒绝，保留原观察文本供原证据判断使用，不添加任何事实。正常响应、其他基线和未约定的错误口径保持。模型、提示、Schema、意图/条件5500及公共事实1800的原输出上限、语义审核、查询预算与确认策略保持。

原始响应先记录，再保存为带 `terminal_failure` 的独立失败缓存；此类缓存没有成功 `result`，不能伪装成模型返回了空提案。外层编译缓存引用同一份原始物理记录；固定回答重放时复用该失败，不重新抽取答案。`compiler_failures.jsonl` 与 compilation.failure 记录整批拒绝、原响应指纹及保留账本的指纹。响应内容不被解析为提案，不依据任务标签更正它。失败缓存、成功缓存及原响应关联均由独立审计核对。

新增 compiler_failure.py 与 test_compiler_failure.py 是本仓库实现，不来自原始上游。此前已完成正常周需用本版本原回答重放并验证一致；旧目录与旧失败保留，新版本独立记账，不能拼接不同版本的半周。

同时将 HTTP RemoteDisconnected（完整响应返回前断开）映射为既有的传输错误，以沿用原来的最多三次、完全相同请求重试。不会为已返回完整答案的语义错误重试，不换模型/渠道，不改变 Jev evaluator 的源码或缓存键。
