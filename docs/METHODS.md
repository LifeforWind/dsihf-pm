# 方法和评测接口

## REN 主方法

运行链为 `run_qwen_ren.py → run_ren_confirmation.py → ConfirmationVerifiedPolicy`。`run_qwen_ren` 是历史文件名，现在按显式 profile 选择中转或本地模型。

1. 从当前公开说明提取新增、改写、取消的意图，保留可核对的原文引述。
2. 由已验证意图账本提供下一次编译的上下文，拒绝的提案不成为未来记忆。
3. 将触发条件拆成合取条件；不确定的 OR/时间关系保持整体，不凭空补条件。
4. Jev 根据实际公开文本和已查询回复判断证据。未知、冲突与明确不成立分别处理；证据在当前公开步之外失效。
5. 对仍有待满足条件的可用来源进行轮询选择；每步最多三次查询，时钟与重复查询均计数，无整周累计查询上限。
6. 执行提交只记为 attempted/inflight。PM-Bench 没有真实执行回执接口，不把提交动作伪装成成功回执。

通用状态机位于 `evidence_needs.py`。自然语言适配位于 `run_ren_natural.py`、`run_ren_grounded.py`、`run_ren_situated.py` 和 `ren_source_compiler.py`；账本权威上下文位于 `run_ren_verified.py`。这些文件是当前运行链的组成部分，不代表多个被混用的主方法。

同 ID 的条件记录只有**内容完全相同**时才确定性合并；同 ID 的冲突内容仍停止。不会任取一条、过滤条件或重新生成答案。

## 横向比较

所有正式入口保持 PM-Bench 原始模拟器、可见提示、隐藏状态 provider、动作映射和 Set-F1 评分器。方法只能接收当前公开提示与真实返回的查询回复；评测器的 groundtruth 不进入方法输入。

| 配置 | 记忆或历史机制 | 重要边界 |
| --- | --- | --- |
| Single / Heartbeat / Hier | 原生运行器与历史 | 使用各自原生交互方式，三次查询限制在访问隐藏 provider 前实施 |
| PIS | 作者 intention store、due 检索；top-5、最多 8000 字符 | 保留原生强制时钟行为，计入预算；无额外八动作执行限制，错误 choose 走原生反馈 |
| PMA | 作者两阶段 MemoryAgent，三类记忆与 BM25 预筛 | 最近七个公开存储单元加当前步；这是 PM-Bench 适配，不是作者训练任务的复现 |
| RAG | 1000 字符块、100 字符重叠；余弦 top-5 | `text-embedding-3-small`，1536 维；无 LLM 抽取/演化/重排序 |
| Mem0 | 官方事实抽取、语义/BM25/实体融合；top-5 | 2.2.1 的 ADD-only v3，不等于早期论文 UPDATE/DELETE 算法；原生格式错误不静默过滤 |

PMA/RAG/Mem0 的决策上下文包含系统、站立计划、当前日计划、当前步查询/修复回复和最多 8000 字符注入记忆。每周重置，周内跨日保留。入库文本移除当前菜单句柄和 A/B/C 干扰项，动作描述为 submitted，不虚构成功。

历史窗口、检索条数、字符上限并非每种方法都存在。文档如实列出适用范围，不将同名参数或不适用参数宣称为全体一致。REN 还使用独立 Jev judge，因此比较是完整系统比较，不能直接归因为单个记忆模块。

## 运行和审核

对外入口固定每步三次、无整周总查询上限；保留有限模型调用、token、费用及传输故障保护。这些保护与观察预算不同。旧 2/126 协议不作为发布入口。

输出保存请求/响应、原生随机标识/时间带、动作、预算和源码哈希。失败目录不会覆盖；新发布入口不自动恢复历史实验。完整轨迹使用官方评分器复算，并禁网络回放缓存；审核会扰动私有标签检查非干扰性。记忆审核对指定浮点诊断量使用原来的 1e-7 容差，动作、文本与请求仍精确比较。

Hier 多数票和全票可通过原作者 `sim/replay_union_votes.py` 从同一 union 轨迹派生，不是独立实时运行。首版不附任何此类派生结果。
